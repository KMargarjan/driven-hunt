1. `src/server/Match/Phase.luau` `maybeRelease` + `src/server/Match/init.luau` `applySpawnBoar` — the two guards that protect a boar release read different data, and when they disagree the release is **dropped**, not held back. `maybeRelease` is called for *every* event that reaches the `Running` branch (`elseif next_.phase == "Running" then ... else maybeRelease(next_, effects, now, event, config)`), but it reads the live count off the event: `local alive = event.aliveBoars or 0`. Only the tick carries it — `Match:step` does `dispatch({ kind = "tick", aliveBoars = boarsAlive() })`, while `watchPlayer` dispatches `{ kind = "join", userId = ..., name = ... }` and `Match.forget` dispatches `{ kind = "leave", ... }` with no `aliveBoars`. So a join or a leave that lands on a step where `now >= state.nextReleaseAt` sees `alive = 0`, passes the guard, and `maybeRelease` commits the release: `state.releasesDone += 1`, emits `spawnBoar`, and `state.nextReleaseAt = now + config.RELEASE_INTERVAL_SECONDS + Phase.jitter(...)`. The owner then refuses it: `if boarsAlive() >= Match.CONFIG.MAX_ALIVE_BOARS then stats.releasesDeferred += 1; return end`. Nothing rolls back `releasesDone` or `nextReleaseAt`, so that boar is never released and never retried: the drive runs five boars instead of six, and `snapshot.boarsLeft` (`BOARS_PER_DRIVE - state.boarsAccounted`) can never reach zero, so the Hud shows a boar that does not exist. This contradicts the design (§6.3: "A deferred release is retried on the next step, not dropped") and REQUEST claim 8 ("holds a release back instead of dropping it when the runtime is full"), which is only true on the tick path. The `pcall` branch in `applySpawnBoar` loses a release the same way (unreachable today only because `BOARS_PER_DRIVE = 6 < Boar.CONFIG.maxBoars = 8`). Required: make one guard authoritative — e.g. carry `aliveBoars = boarsAlive()` on every event `dispatch` hands to `Phase.step` so the pure guard is the only one that decides, or have the owner feed a genuine retry back into the machine instead of returning silently — and add a `match_phase`/`match_live` assertion that drives a non-tick event at a release moment with the runtime full and shows the release still happens.
