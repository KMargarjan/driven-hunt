1. `tests/client/map_ui.spec.luau` "puts every landmark at the SAME pixel the render script painted it at (0 px)" / `tools/map_paint.py` `landmarks` + `tile_plan.world_of_box` — **the alignment case is an algebraic identity and survives deletion of the painter.** Evidence: `landmarks.place` computes the landmark's canvas pixel as `cx = (x - x0) * pps`; `found` stores `pxX = (cx - left) * out_w / float(right - left)`; `tile_plan.world_of_box` writes the rect as `minX = x0 + left / pps, maxX = x0 + right / pps`. So `pxX / out_w ≡ (worldX - rect.minX) / (rect.maxX - rect.minX)` **by construction, for any world point, any tile and any `pps`** — `world_of_box` is the exact inverse of `place`'s mapping. The spec's two sides are `left + mark.pxX / size.width * width` and `MapUi.rawOffsetPx(mark.worldX, ...)`, and since `rawOffsetPx` is `(worldX - view.centreX) * view.pxPerStud` the common factor cancels: the comparison reduces to that identity, which is why it prints `worst 0.000000 px`. **Nothing in the chain reads one pixel of one PNG.** Delete `paint_canvas` entirely, or replace all nine PNGs with blank images, and the case still passes and still prints 0.000000 px — the only thing offered as proof that the painted roads lie under the drawn icons. The same identity is the whole content of claim 8's cited round-trip, `selftest`'s *"a tile rect round-trips every landmark at %.2f px/stud"* (`fx = (mark["worldX"] - rect["minX"]) / (rect["maxX"] - rect["minX"]) * mark["outW"]` against `mark["pxX"]`), so that check is hollow too (`check_tiling`'s shared-boundary half is real and is not in question). The claim that the sides are independent is asserted three times and is false: `landmarks`' docstring *"so map_ui.spec compares two independent expressions rather than one expression with itself"*, `cmd_render`'s *"two independent instruments, which is the only kind of alignment claim worth making"*, and the spec's *"ITS TWO SIDES ARE DIFFERENT INSTRUMENTS"*. Note also that the painter's projection is a **duplicate**, not a shared call: `paint_canvas` defines its own `def to_px(x, z): return (x - x0) * pps, (z1 - z) * pps` and `landmarks.place` re-writes the same two lines, so changing the painter's projection would not redden anything. Required: make `landmarks` use the *same* `to_px` the painter uses (one function, not two copies), and add a check that reads the saved image — e.g. for each `road*` landmark assert the pixel at `(pxX, pxY)` in the saved tile is the verge/carriage colour (`968f58`/`ab9a6d`) and that a control pixel one road-width off the centreline is **not**; failing that, delete the "0 px / two independent instruments" wording from the request, the spec comment and `map_paint.py` and report the picture's alignment as unmeasured.

2. `src/client/Hud/MapUi.luau` `drawGeometry`'s painted loop vs `MapUi.paintedRectPx` — **the "0 px" number is measured on a rectangle the drawer does not draw.** Evidence: `paintedRectPx` returns the raw `left, top, right - left, bottom - top`, and that is what the spec compares; the drawer then places the image at `UDim2.new(0.5, math.round(left), 0.5, math.round(top))` with `Size = UDim2.fromOffset(math.max(1, math.round(width)) + painted.BLEED_PX, math.max(1, math.round(height)) + painted.BLEED_PX)`, `BLEED_PX = 1`, `ScaleType = Stretch`.
