1. `tools/meshy.py` / `cmd_fetch` — a fetch that lands **no texture map at all** exits 0, prints the second-stop-point line and invites Karen's yes, after the refine (the most expensive step in the chain) was paid for precisely to produce those maps. Evidence: the download loop computes `undownloaded` (`except Failed ... undownloaded.append(name)`) and then **never reads it again** — the only consumer is the FBX branch, `if "model.fbx" not in written:`. `validate_fetched` only iterates artefacts already in the record (`written = {artefact["name"]: artefact for artefact in entry.get("artefacts", [])}`) and has no check that any `texture_*.png` exists, so an empty `texture_urls` in the re-poll, or a 403 on every signed map URL, produces `[meshy] OK: fetch ... files=2` plus "OPEN IT AND LOOK AT IT (rule 5), then ask Karen". 2. `tools/meshy.py` / `cmd_fetch` + `RESUMABLE_STATES` — a validation failure strands a paid run: **no command can retry it**, including the one failure the code itself calls re-fetchable. Evidence: `cmd_fetch` sets `record["state"] = "fetched"` *before* `if problems:`, so a truncated download (problem text: "`{name}` on disk does not match the sha256 that was downloaded", commented "A TRUNCATED DOWNLOAD IS THE 3-DAY TRAP'S CRUELLEST FORM") leaves state `fetched`. `RESUMABLE_STATES` is generated only from `PHASES = ("preview", "refine", "remesh")`, so `cmd_resume`'s `if record["state"] not in RESUMABLE_STATES: raise Refused(...)` refuses it; `cmd_fetch`'s own `require_state(record, "remesh-ready")` refuses it; `cmd_remesh` needs `refine-ready`; `cmd_refine` needs `approved`. The printed line offers no way forward either: "the files are in <runs-dir>/... and the credits are spent".
