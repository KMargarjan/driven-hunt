# Research: the Meshy API and the ASSET agent (Task 55)

Written 2026-09-26 by the Builder, **before any code** (rule 1). The design
(`docs/design/meshy-tool.md`, Architect, Task 53) was written by a session that **could not fetch
anything** — its §0 item 1 says so — and it listed ten strings in §10.1 that this note had to nail
down first. All ten are answered below, **fetched and quoted on 2026-09-26**, and **seven of them
change something**.

Design: `docs/design/meshy-tool.md` · Brief: `reviews/task-53/BRIEF.md`

## What the system must do

Turn one written brief into one Roblox-ready mesh, with **two stop points a human owns**: Karen looks
at the preview before any refine credits are spent, and Karen approves the model before it is uploaded
to Roblox. The key never reaches the repo, the logs or a report. Output is downloaded in the same
session it is made, because Meshy deletes it after three days. Provenance replaces reproducibility,
because Meshy has no seed.

## Sources

1. **Meshy API — Text to 3D**, <https://docs.meshy.ai/en/api/text-to-3d> · read 2026-09-26. Official,
   current. **Good:** names every request field and the whole response schema, including the field the
   design most needed (`consumed_credits`). **Bad:** says nothing about retention — that lives in the
   Terms, not the API docs, so a reader of the API docs alone would build a pipeline that 404s on day
   four.
2. **Meshy API — Image to 3D** <https://docs.meshy.ai/en/api/image-to-3d> and **Multi Image to 3D**
   <https://docs.meshy.ai/en/api/multi-image-to-3d> · read 2026-09-26. Official. **Good:** both accept
   *"A base64-encoded data URI of the image"*, so a local PNG needs no public hosting — which is what
   makes `references` in the brief work at all without a bucket. Multi-image takes *"1 to 4 images"* in
   `image_urls`. **Bad:** the single-image page does not link the multi-image path; it had to be
   fetched separately.
3. **Meshy API — Remesh**, <https://docs.meshy.ai/en/api/remesh> · read 2026-09-26. Official.
   **Good:** `topology` is *"quad"* or *"triangle"*, and `target_polycount` accepts *"100 to 300,000
   (inclusive)"*. **Bad:** the response carries `model_urls` and **no polycount or statistics field**,
   which settles design §10.1 item 5 the unhelpful way (see D5).
4. **Meshy API — Rate limits**, <https://docs.meshy.ai/en/api/rate-limits> · read 2026-09-26.
   Official. **Good:** 20 req/s for Pro/Premium/Ultra, 100 for Enterprise; concurrent *queue* caps of
   10 / 30 / 100 / 20; and 429 **distinguishes the two**: *"RateLimitExceeded"* for request hits and
   *"NoMoreConcurrentTasks"* for queue hits. **Bad:** `Retry-After` is **not mentioned**, so a backoff
   that depends on it would depend on an undocumented header.
5. **Meshy API — Authentication**, <https://docs.meshy.ai/en/api/authentication> · read 2026-09-26.
   Official. **Good:** *"The `Bearer` prefix in the header value is mandatory"*, and the example key is
   `msy_` followed by a long token — the shape `tools/privacy_scan.py` now guards. **Meshy's own
   example key is deliberately NOT quoted in full here**: the new `meshy-key` rule catches it, and
   a scanner that has to be taught an exception for documentation is a scanner that will one day
   be taught one for a real key. The prefix is the load-bearing part and the prefix is quoted.
   **Bad:** it does **not** say an API key needs a paid plan, which the brief asserted; only that a
   Meshy account is needed. Recorded as unconfirmed rather than repeated (D7).
6. **Meshy API — Errors**, <https://docs.meshy.ai/en/api/errors> · read 2026-09-26. Official.
   **Good:** a failed task's message is at **`task_error.message`**, and `task_error` carries `type`,
   `message`, optional `code` and `doc_url`. 401 is *"No valid API key provided or the API key provided
   is not authorized"*.
7. **Meshy Terms of Use**, <https://www.meshy.ai/terms-of-use> · **last updated 19 September 2026**,
   read 2026-09-26. **Good:** it answers ownership and retention in one place, in sentences short
   enough to quote. **Bad:** the ownership sentence is split across a free-plan clause and a paid-plan
   clause, so quoting half of it inverts the meaning.
8. **`meshy-dev/meshy-cli`**, <https://github.com/meshy-dev/meshy-cli> · read 2026-09-26. **MIT**,
   **TypeScript**, official (*"the official Meshy API"*), 49 commits. **Good:** it is a working
   reference for request shapes. **Bad:** TypeScript and a Node dependency tree, in the one program in
   this repo that holds a secret. **Not adopted as code** — see "Borrowed, not invented". The brief
   named the org as `MeshyAI`; it is **`meshy-dev`** (D8). No `meshy-mcp-server` repo was found in that
   org, contrary to the brief.

## Borrowed, not invented (rule 2)

**Adopted:** the request and response *shapes* from sources 1–3 verbatim, the two-phase
preview→refine flow (Meshy's own model, not ours), the `msy_` bearer header, and the polling loop.
**Not adopted:** `meshy-cli` itself. The reason, written down as rule 2 demands: it is MIT and would
be legal to vendor, but it is TypeScript with an npm dependency tree, and this is the one program in
the repo that reads a secret — `docs/design/asset-pipeline.md` §7 made the identical call for the
identical reason. `tools/meshy.py` is stdlib-only Python, matching `tools/studio_mcp.py` and
`tools/privacy_scan.py`. **Nothing structural is invented**: the state machine, the ceilings and the
stop points are this project's own process, not a reimplementation of anything Meshy ships.

Two more facts that no §10.1 item asked for and that the tool needs:

- **D7. The "API keys need a paid plan" claim is NOT in the authentication docs.** They say only that
  *"Meshy API requires you to have a Meshy account to create and manage API keys."* The tool therefore
  does not tell the operator their plan is the problem as a fact; its 401/403 message lists it as one
  possible cause among the others.
- **D11. `GET /openapi/v1/usage/tasks` costs no credits but is NOT available on Karen's plan.** *"The
  API key must belong to a **Studio** or **Enterprise** team; keys on any other plan, or with no team,
  receive a `403`."* So the Director's "at most one real call that costs nothing" is available as
  `meshy.py key --check`, but on a Pro/Premium/Ultra key it will answer **403, and a 403 there proves
  the key was transmitted and rejected for plan reasons, not that the key is wrong**. The tool says
  exactly that, and `key` without `--check` makes no network call at all.

## Licence and ownership, quoted in full

- **Paid plans own the output:** *"such customers on a paid Meshy plan own their Customer Output."*
  The free-plan clause immediately above it says the opposite — *"Meshy owns all right, title, and
  interest, including all intellectual property rights, in and to the Customer Output"* — which is why
  the sidecar's `licenceBasis` is `meshy-paid-owned` and **never anything else from this tool**: on a
  free plan, nothing this pipeline produces could ship.
- **Training, and it applies to Karen:** *"Meshy may use Customer Inputs and Customer Outputs
  (collectively, 'User Content') from non-Enterprise Customers to train, validate, test, or improve
  Services unless otherwise agreed to in the Order."* Paid is not Enterprise. **This is Karen's
  decision item 2 in the brief, and the default the Director recorded is accept.** It is written here
  so the decision is on the record rather than assumed.
- **Retention:** the D9 sentence above.

- **D12. `texture_resolution` is a STRING, and there is no 1k.** Re-read on 2026-09-26 at
  <https://docs.meshy.ai/en/api/text-to-3d> (the Text to 3D reference, refine task creation), after
  the first real refine came back **`HTTP 400: texture_resolution must be a string`** — with Karen's
  20-credit preview already paid for. The reference documents, for the refine body:

  > `mode` (string): `"refine"` · `preview_task_id` (string) · `enable_pbr` (boolean, default
  > `false`) · **`texture_resolution` (string): `"2k"`, `"4k"`, or `"8k"` (default `"2k"`)** ·
  > `texture_prompt` (string) · `ai_model` (string): `"meshy-6-lite"`, `"meshy-6"`, `"meshy-7.1"`
  > or `"latest"`

  Three consequences, all in `tools/meshy.py` (Task 64):
  1. The tool sends `"2k"` / `"4k"` / `"8k"`, never a pixel count.
  2. **There is no 1k.** `docs/asset-briefs/tree.oak_v1.brief.json` asks for `texturePx: 1024`
     (asset-pipeline §12.2's budget for an ordinary key), which the API cannot be asked for; that run
     is refined at `"2k"` and must be **downscaled downstream**. The pair asked/meant is recorded on
     the run as `textureResolution`, and `validate_fetched` judges the maps against what was asked
     for rather than against a number the API was never told.
  3. Every field this tool sends now has its documented type in one table, `REQUEST_FIELDS`, checked
     before the body leaves the builder **and** again inside `request`. The old selftest froze
     `"texture_resolution": 2048` — a fixture written from the code instead of from the
     documentation, so the one test that could have caught this agreed with it.

- **D13. The remesh answers with a GLB unless it is asked for more, and it is the DELIVERABLE.**
  Re-read on 2026-09-26 at <https://docs.meshy.ai/en/api/remesh> after `fetch` stopped twice on
  `boar.body_v1-20260926T1501Z` with "model.fbx did not reach disk", 35 credits spent. The request
  body documents:

  > `target_formats` (string[], default **`["glb"]`**): "A list of target formats for the remeshed
  > model. Available values: `glb`, `fbx`, `obj`, `usdz`, `blend`, `stl`, `3mf`."

  and the response's `model_urls` is documented as holding URLs "organized by format" — `glb`, `fbx`,
  `obj`, `usdz`, `blend`, `stl`, `3mf` — beside `thumbnail_url`, `alpha_thumbnail_url`, `id`, `type`,
  `progress`, `status`, `created_at`, `started_at`, `finished_at`, `task_error` and
  `consumed_credits`. **There is no `texture_urls` and no polycount or statistics field**, which
  confirms D5 and item 3 from the other side.

  So the run that stopped was not broken: it asked for nothing and got the default, one GLB. Three
  consequences (Task 67):
  1. `target_formats: ["glb"]` is now SENT, so the deliverable is asked for rather than inherited.
     Asking for `"fbx"` as well is one word here and one more paid remesh to prove; it is queued as
     67a rather than tried on Karen's credits.
  2. `DELIVERABLE_MODEL = "model.glb"` — what `fetch` requires, validates and names at the second
     stop point. **Director decision, 2026-09-26:** for a remeshed run the remeshed GLB *is* the
     model deliverable, because Studio's 3D Importer takes it directly.
  3. **The model is never taken from the refine task.** The maps are (the refine is what was paid
     for them, D12), but the refine's model is the high-poly one the remesh exists to replace.

- **D14. What Roblox's own documentation says about the two formats, quoted — and what it does not.**
  Read 2026-09-26.
  - `create.roblox.com/docs/art/modeling/3d-importer`: *"You can import meshes in the .fbx, .obj, or
    .gltf format."* **It does not name `.glb`.** `.glb` is the binary container of glTF and Studio
    accepts it in practice; that is the Director's decision above, and **nobody in this project has
    yet imported one** — the first import of `model.glb` is the measurement, and until it happens
    D13 item 2 rests on the decision, not on a source.
  - `create.roblox.com/docs/art/modeling/texture-specifications`: *"Roblox supports up to 4096×4096
    pixel texture resolutions (4K)"*, and on what happens to a big one: *"the engine automatically
    starts with lower quality versions of the texture and ramps up quality based on device
    resources."* A separate line, about UV space rather than upload, reads *"Roblox supports up to
    1024×1024 pixel spaces for texture maps."*
  - **What this does and does not support.** A 4096 map is INSIDE Roblox's stated limit, so an
    oversized map is a brief violation, not a platform one — `meshy.py` reports it and resizes
    nothing. The claim that Roblox *downsamples on upload* is **not** in what was read; what is
    documented is runtime quality ramping. Recorded that way on purpose: an assumption about the
    platform is how a texture budget stops meaning anything.

## The numbers

Everything in design §12 is unchanged by this note except where a delta above moves it. The ones this
note establishes rather than inherits:

| Quantity | Value | Basis |
|---|---|---|
| `target_polycount` accepted range | **100 – 300,000 inclusive** | Meshy, source 3. `REMESH_CEILING = 18,000` and `boar.body = 6,000` are both well inside it |
| `target_polycount` default if unsent | 30,000 | Meshy, source 3 — above Roblox's 20,000 limit, so this tool **always sends the field** |
| Requests per second | 20 (Pro/Premium/Ultra) | Meshy, source 4. `MIN_REQUEST_GAP_S = 1.0` is 5 % of it |
| Concurrent queued tasks | 10 / 30 / 100 by plan | Meshy, source 4. `MAX_TASKS_PER_RUN = 4` cannot reach the smallest |
| Output retention | **72 h from `created_at`** | Meshy Terms, source 7, D9 |
| Roblox mesh limit | 20,000 triangles | `docs/design/asset-pipeline.md` §11 source 4 |
| Texture asked for | `texture_resolution = "2k"` (2048 px) | a real parameter (D3) and a **string** (D12); inside Roblox's 4096 |
| Texture sizes the API offers | **`"2k"` (2048), `"4k"` (4096), `"8k"` (8192)** | Meshy, D12. **No 1k**: a 1024 brief is refined at 2k and downscaled downstream |

## What this note could not settle

- **Whether Karen's key is on a plan whose output she owns.** The Terms make ownership conditional on
  "a paid Meshy plan"; the brief says she is. Nothing the tool can call proves the plan — `usage/tasks`
  answers 403 for every plan below Studio (D11) — so `licenceBasis = "meshy-paid-owned"` rests on
  Karen's statement, recorded in the run record, and not on a measurement.
- **Whether `Retry-After` is ever sent on a 429.** Undocumented (source 4). The tool honours it if
  present and otherwise backs off 2/4/8 s; it does not claim the header exists.
- **The real credit cost of a preview.** `consumed_credits` is returned per task, so it will be
  recorded — but no figure here is measured, because this task spends nothing.
- **Anything about the generated geometry.** No triangle count is parsed and none can be (D5, and
  `docs/PROJECT_CONTEXT.md`'s "a hand-written FBX reader" is one of the three named causes of death of
  the previous project). The number is declared and Roblox's importer is the enforcer.
